# 视觉与交互规范

模板（`assets/template/`）是多部剧本共用的。**不要为了某一剧去改模板**——
该剧的差异写进它的 `site_meta.json`。只有当多数剧本都需要同一种新能力时，
才改模板，且改完必须重建所有已有剧目确认没打破别的站。

> 2026-11 审查后的规范。旧版是「深色墨底」，现已改为**亮色宣纸底优先**：
> 用户明确要求「不要暗色」，且浅底更适合红色题材的庄重感。
> 深色仍支持（`normalizePalette` 按底色明度自动切 `data-theme`），但默认是浅色。

## 一、基调

**宣纸米黄底 + 墨色正文 + 一个收敛的主色 + 一个点睛的旧书金。**
文字用宋体（衬线），导航与说明用黑体（无衬线），数据用等宽。
主色只给标题、印章、分隔线，不铺面。

三层质感叠在一起，这是「旧书」感的来源：

| 层 | 实现 | 成本 |
|---|---|---|
| 纸纤维 / 帘纹 | `.paper-fibers` 双层 `feTurbulence` + 帘纹渐变，`mix-blend-mode: multiply` | 高（见性能一节） |
| 茶渍霉斑 / 泛黄纸边 | `.page::before/::after` + 渐变 | 低 |
| 立体字 | `.hero-title-3d` 双层伪元素挤出 + 指针视差 | 低 |

参考实现：《山河摆渡人》剧本站（`https://zhouyaobai.github.io/shanhe-baiduren/shanhe/`）——
左幕次轨、顶部滚动联动、HERO 全屏场景、主线时间轴、逐幕资料卡、曲目卡、
歌单墙、曲目表、人物卡、伏笔卡、AES 密文权限门。
《百年星语·破晓1928》在它之上多了：创作总纲、同曲异形、人物同台图、⌘K 全剧检索、
台本 / 沉浸双模式、字号调节、角色台词过滤。

## 二、配色

`site_meta.json` 的 `palette` 只写要覆盖的键，其余取默认（浅色）：

### 「朱砂为骨」四色（默认色板）

底色分两级：**底比卡片沉一档**。这一档之差就是全部的层次 ——
卡片不用靠阴影撑着，自己就浮起来了。

**红色歌剧，红必须是结构色，不是点缀。** 默认色板据此重排：
中性色往**暖红宣纸**靠（避开土黄 / 卡其 —— 那是「旧」，不是「红歌剧」），
朱砂从「点缀」升级为「骨架」。

| 键 | 默认 | 用途 |
|---|---|---|
| `bg` | `#EFE5D8` | 页面底色 · 暖红宣纸（沉） |
| `bg2` | `#FBF6EE` | 卡片底色 · 亮纸（亮一档） |
| `bg3` | `#E2D3C2` | 抬升面（深块、吸顶表头底） |
| `paper` | `#241811` | 主文字（墨色） |
| `paper2` | `#574235` | 次文字 |
| `paper3` | `#755E4E` | 弱文字（眉标、注脚） |
| `accent` | `#B22D1D` | 结构色：**朱砂** · 印章、眉标、幕题、按钮、序号 |
| `accentDeep` | `#8A1E13` | **深朱砂** · 大面积实底（幕次轨、表头、界栏） |
| `accent2` | `#806010` | 配角：**灯油金**（火）· 只做灯火与描边，不承担小字 |
| `accent3` | `#33486B` | 配角：**靛青**（夜的冷光）· 冷投影、3D 暗面 |

**为什么分成两个红。** 大面积铺红会闷、会脏，红色歌剧又不该只有一点红。
解法是**红做结构、米金做阅读面**：深朱砂只给三处实底 ——
幕次轨（书脊）、表头（节目单）、界栏（朱丝栏）；其余靠线、靠印、靠眉标。
朱砂本身做「亮一档」的结构色：章节方印、幕题毛笔、主标题、按钮、曲序小印。
读面（卡片、正文、纸纹）保持米白，红色因此跳得出来，又不压人。

**金色会发绿。** `--accent-2` 是压深的灯油金，单独用在铜箍、灯焰上还行，
一旦当**小字色**就发橄榄绿，一眼旧。11–13px 的标签
（表头、`.sc-act`、`.cast-role`、`.thread dt`、`.mf-sec`）一律走朱砂。
铜箍一类要金属感就掺亮金（`color-mix(in srgb, var(--accent-2) 34%, #F4DFA6)`），
红漆木盖则用朱砂配一道金箍 —— 红木盖 + 金边的组合比整圈暗金更像「红灯笼」。

**冷暖成对（3D 的底子）。** `accent2` 取灯火的暖，`accent3` 取夜的冷 ——
**冷暖成对，3D 才立得住**：受光面走金，背光面走靛青，卡片浮起才有体积。
写深色剧目时 `accent3` 比 `accent2` 更适合做次级强调，因为它天生就是冷色。

**`accentDeep` 与 `on-accent-deep` 是 2026-11 第四轮新增的。**
深朱砂底的面积比朱砂大得多，反白必须**按深底单独算**
（`pickOnAccent(accentDeep)`），不能借用朱砂底那一档 ——
中间调的 accent 反白未必在深底上也够。构建时是九项契约里的一项。

### 冷暖成对（3D 的底子）

投影不要用单一灰。**暖光从灯那边来，影就该分两半**：

```css
box-shadow:
  0 2px 0 color-mix(in srgb, var(--paper-edge) 70%, transparent),  /* 纸边厚度 */
  var(--shadow-warm),   /* 灯油的暖影 */
  var(--shadow-cool);   /* 靛青的冷影 */
```

只用一层灰影，卡片就是「浮在纸上」；冷暖分开了，它才「被照亮」。

### 对比度下限（硬约束 · 构建时强制）

**所有正文级文字 ≥ 4.5:1，大字号/纯装饰 ≥ 3:1。**

**这一条已经写进构建脚本，不需要人记。** `build-site.mjs` 的 `normalizePalette()`
在生成 `palette.css` 之前逐项验算下面这张契约表，不合格的**自动压深/提亮到合格**
为止，并把实测比值打印出来：

```
✓ paper      正文          13.90      ✓ accent-3   靛青          7.40
✓ paper-2    次级文字       7.54      ✓ accent-deep深朱砂         7.41
✓ paper-3    弱化文字       4.87      ✓ on-accent  反白按钮      5.97
✓ accent     强调红         5.13      ✓ on-accent  深朱砂反白   8.62
✓ accent-2   暗金          4.69
```

九项里最容易漏的是 **「深朱砂反白」**：表头、幕次轨这些实底面积大，
反白必须按深底单独算，不能借用朱砂底那一档。
早前版本还有「accent-2 配表头底」一项 —— 表头改成朱砂实底后它就不适用了，
现在表头的字一律是 `--on-accent-deep`。

**改色规则**：金色一旦当小字色就会发橄榄绿（暗金压深 ≈ 橄榄）。
**11–13px 的标签一律用朱砂**，金色只留给灯火与描边。
真要金色文字，压深到 ≥ 4.5，**往深里压别往亮里提** —— 亮金会变糖果色，
也就不庄重了。

**看到构建输出里有「对比度不足，已自动校正」就说明色板写歪了**，
自动校正只是兜底，回头还是要把 `site_meta.json` 里的值改成合规的那个，
免得每次构建都靠兜底。

配色写进 `assets/css/palette.css`（构建时生成），`tokens.css` 只管尺度与字体。

## 三、背景景别

`site_meta.json` 的 `scene` 选一种，`assets/js/scene.js` 用 Canvas 2D 程序化生成，
零依赖、几 KB，配色自动跟随 CSS 变量：

| 景别 | 画面 | 适合 |
|---|---|---|
| `mountain` | 层叠山脊剪影 + 月晕 + 谷雾 | 山地、历史、远征 |
| `river` | 对岸山 + 水面月路 + 波纹 | 渡口、江水、迁徙 |
| `fire` | 暖色火光 + 上升火星 | 火塘、炉边、动荡年代 |
| `sea` | 地平线 + 浪线 + 月光 | 海城、远行、离别 |
| `stage` | 追光 + 幕布褶 + 尘埃 | 剧场、实验、意识流 |
| `forest` | 纵深树干 + 萤火 | 山林、童话、记忆 |

场景支持指针视差；在 HERO 上按住拖动可拉开景深。

## 四、页面区块

顺序固定，数据为空则自动隐藏：

1. **HERO** — 全屏场景 + 毛笔立体剧名 + 印章 + 题旨 + 署名 + 开演按钮 + 续读卡
2. **主线** — 时间轴，点条目跳到对应幕（窄屏转竖排）
3. **创作总纲** — 剧本开头的总纲做成可展开卡片墙（`front`）
4. **剧目** — 逐幕：眉标 / 幕名 / 时间·地点·人物 / 舞台氛围 / 场次 / 台词 / 曲目卡
5. **权限门** — 仅在 `gate.enabled` 且设了密码时出现
6. **歌单** — 卡片墙，点开看完整歌词
7. **曲目表** — 幕次 / 序号 / 曲目名称 / 类型 / 演唱，序号可点跳
8. **同曲异形** — 同一支曲子在剧中的多种形态
9. **人物** — 同台关系图 + 徽记 + 姓名 + 身份 + 小传
10. **伏笔** — 埋 / 收 / 点评三段
11. **页脚** — 结语 + 声明 + 署名

## 五、权限门

剧透正文与歌词存在 `SCRIPT_SECRET` 里（AES-256-GCM）。未解锁时：

- 幕内只显示场次标题与曲目卡，正文位置显示「输入密码阅读全文 →」
- 歌词区做模糊 + 禁止交互
- 权限门区块常驻页面（幕与歌单之间）

输入正确密码后：合并受限层 → 重绘幕与歌单 → 权限门区块消失。
解锁状态存 `sessionStorage`，关标签页即失效。

**密码走环境变量 `READ_PASS`，永不写进仓库。**

## 六、3D 分层与降级

3D 资产：毛笔标题双层挤出、卡片离纸（透视微转 + 指针高光）、幕题叠影厚度、
幕间海报翻页、幕次轨书脊装订线、**HERO 的马灯**。

### 马灯（HERO 右侧那盏灯）

HERO 的右半边长期是空的 —— 一块白地，最容易显得"没做完"。
模板的做法是放一盏**马灯**：全剧的意象，也是全站唯一光源。

```
八面纸屏绕竖轴拼成的柱体
  ├─ .lantern-panel × 8   rotateY(i*45deg) translateZ(96px)
  ├─ .lantern-flame      screen 混合，纸从里面被照亮
  ├─ .lantern-cap/foot   上下盖（椭圆）
  └─ .lantern-tassel     流苏
```

四个做对的要点，抄走即可：

1. **纸屏的侧边几乎不圆**：`border-radius: 10% 10% 12% 12% / 24% 24% 28% 28%`。
   水平半径给大了，每片面都鼓成一颗蛋，八片摆一起像三颗，
   不是灯。水平只留 10%（侧边近乎笔直，是竹骨），上下才收口。
2. **八片要有明暗梯度**：正面最亮，转到侧面依次压暗（`--shade: 0% → 46%`）。
   八片一样亮就成了折屏，读不出圆柱。
3. **火焰用 `mix-blend-mode: screen` 放在纸屏之前**（`translateZ(6px)`）：
   纸被从里面照亮，而不是被从外面打亮。
4. **指针转面压在 ±13°**（`initLantern3D()`）：再大就转成风车，庄重感全丢。

**窄屏把灯挪到标题上方**（`.hero-lantern-slot { order: -1 }`），像海报顶上挂的一盏。
窄屏别用绝对定位摆灯 —— HERO 高度随剧目变，绝对定位的灯迟早压到字上；
用文档流（`order: -1` + 定高槽）才稳。

**`motif` 字段可以关掉它**：`site_meta.json` 写 `"motif": "none"` 即整块移除。

**门控是硬约束，缺一不可：**

```css
@media (hover: hover) and (pointer: fine) { /* 触屏不触发 tilt3d / 指针高光 */ }
@media (max-width: 720px)              { /* 3D 退回平面，标题只留一层挤出 */ }
@media (prefers-reduced-motion: reduce){ /* 全部静止，伪元素移除 */ }
@media (hover: none)                   { /* 锚点按钮常驻半透明 */ }
```

### 三道门控必须 CSS 与 JS 同时成立

JS 侧的 `pointermove` 监听**不能只判 `(hover: none)`**——那比 CSS 宽。
触摸屏笔记本同时满足 `hover: hover` 与 `pointer: none`，手指一划就把卡片
转起来而不是滚动页面；门控放宽 = 手机上「页面自己会动」，庄重感全无。

`main.js` 的 `motionOk()` 三条全中才挂监听：

```js
const motionOk = () =>
  window.matchMedia('(hover: hover) and (pointer: fine)').matches
  && !window.matchMedia('(prefers-reduced-motion: reduce)').matches
  && window.innerWidth > 720;
```

**条件在运行时会变**（窗口缩小、系统切到减少动效），所以监听要能摘能挂：
`onMotionGateChange()` 监听三个 `matchMedia` 的 `change` 事件，失效时把
已经转起来的元素立刻放平——不能等下次刷新。

标题的 transform 写在**行内样式**上，权重压过任何 CSS 规则，
所以「窄屏退回平面」只能靠 JS 断开监听，CSS 拦不住。

### 纸层卡片（不是玻璃卡片）

卡片浮起的读法有两种：玻璃（半透明白 + 白高光）和**纸**（抬起一页纸）。
旧书要的是后者：

```css
.tilt3d::before {                       /* 底下那张纸，露出一条边 */
  content: ""; position: absolute; inset: 0; z-index: -1;
  background: var(--paper-edge);
  opacity: 0; transform: translate3d(0, 0, -4px);
}
.tilt3d:hover::before { opacity: 1; transform: translate3d(-3px, 4px, -6px); }
```

指针高光也要跟着光走 —— 暖光从灯那边来，高光就不该是正中一片白，
而该是偏上偏右的一团暖色。`--mx` / `--my` 记录指针位置，
高光的径向渐变就用它们定位。

### 窄屏 3D 块必须写在 CSS 最后

`.tilt3d:hover`、`.front-card:hover` 的选择器权重是 **(0,2,0)**，
高于 `.tilt3d` 的 (0,1,0)。窄屏块写在前面，鼠标一划卡片照样翘起来——
「窄屏退回平面」就成了空话。所以窄屏块要同时满足：

1. 放在文件**最后**（`main.css` 末尾的「响应式补丁」一节）
2. 选择器权重与 hover 规则**相同**（`.tilt3d:hover { transform: none }`）

窄屏要保留**非交互式立体**（成本 0 且不掉帧）：幕题的 `text-shadow` 叠影、
纸的帘纹纤维、一次性 IntersectionObserver 触发的幕间海报翻页、
以及毛笔标题的**两层挤出**（`::before` / `::after` 的 `translateZ`）——
这个是静态的，不随指针动，窄屏必须留着，它就是「大气」的主要来源。
「3D 关掉 = 页面变平」要有落点，否则手机端像没做完。

## 七、响应式（2026-11 审查后重写）

### 断点

| 宽度 | 布局 |
|---|---|
| ≥861px | 表格不横向滚动，**表头纵向吸顶**（`top: var(--topbar-h)`） |
| 861–1000px | 幕次轨隐藏，顶栏保留 |
| ≤860px | 宽表横向滚动 + **首列吸附**；同台图降级为角色徽章 |
| ≤720px | 顶栏两行；时间轴转竖排；3D 退回平面 |
| ≤420px | 人物卡一列，品牌再收窄 |

### 手机顶栏必须两行

390px 塞不下「品牌 + 七个导航 + 五个工具」——单行必然折行并**溢出到正文上**
（`.topbar` 高度锁死，导航折行后掉出磨砂底）。所以：

- **上行**：品牌（`text-overflow: ellipsis`，≤88px）+ 工具区
- **下行**：导航横向滚动条（`flex-wrap: nowrap; overflow-x: auto` + 右侧渐隐遮罩）
- 工具按钮 **≥ 44×44**（iOS 触控下限）；导航项也 **≥ 44px 高**
- 窄屏**不要隐藏**任何导航项——横向滚动条里都放得下
- `--topbar-h` 必须等于**实际渲染高度**：两行顶栏（6px 上边距 + 44px 工具行
  + 44px 导航行）= **94px**。写成 92px 会让吸顶表头与正文留白差 2px。
  改导航高度就同步改这个变量，验收时对一遍 `getBoundingClientRect().height`。

### 响应式规则必须写在 CSS 文件末尾

`main.css` 上半段的「增强层」重新定义了 `.hero` / `.song-body` / `.paper-fibers` /
`.tools` / `.spine-items` / `.tilt3d` / `.front-card` / `.hero-title-3d` 等。
响应式块若排在它们前面会被**整段吃掉**——手机上看到的一直是增强层的桌面值。
（这是审查里最隐蔽的一个系统性缺陷。）

**规矩：要覆盖增强层那些选择器的断点规则，写在文件末尾的「响应式补丁」一节。**
与基础规则不冲突的断点块就地放着也无妨；**拿不准就放末尾**——
放末尾永远不会错，放前面可能会被吃掉。

增强层重定义过的选择器（改动前先对一遍这张表）：

```
.hero  .hero-title  .hero-title-3d  .song-body  .paper-fibers  .tools
.spine-items  .tilt3d  .front-card  .rail-item  .cmdk  .spine-dot
```

### 触控目标补齐（窄屏统一兜底）

模板末尾的「触控目标补齐」一节把这些都拉到 44×44：
导航项 / 芯片 `.chip` / 幕次锁与全纲锁的「输入密码」按钮 /
同曲异形里的歌名跳转 `.mf-name button` / 伏笔的「场 N」跳转 `.thread-jump` /
检索面板输入框与关闭键 / 角色筛选条清除键 / 回到顶部。

验收脚本要**排除掉真正不可见的元素**（`display:none`、祖先 `opacity:0`、
祖先 `pointer-events:none`），否则会得到一堆假阳性。
`.to-top` 未显示时是 `scale(.9)`，量出来 40×40 —— 属正常，显示后是 44×44。

### 其他必查项

- 栅格子项必须 `min-width: 0`——grid item 默认 `min-width: auto`，
  会被表格的 `min-width` 顶破，把整页撑出横向滚动（手机上是「内容被裁掉且够不着」）
- 横向滚动容器**不能**同时做纵向吸顶：`overflow-x: auto` 的计算 `overflow-y` 会变 `auto`，
  sticky 的参照系变成那个不纵向滚动的容器，`top` 值会把表头整体顶下容器边缘、压掉第一行。
  要吸顶就撤掉滚动容器（宽屏），要横滑就只留首列吸附（窄屏）
- 同台关系图这类 SVG 在手机上缩到 0.31 倍后字号只剩 4px，**必须**换列表/徽章呈现
- 全屏 `mix-blend-mode: multiply` 合成层是低端安卓掉帧的头号嫌疑，
  窄屏降级（去湍流层、降 opacity、去 blend）

### 打印

`@media print`：隐藏场景/顶栏/幕次轨，展开全部曲目正文，黑字白底。

## 八、可访问性

- 语义标签（`header` `nav` `main` `section` `footer` `dl`）、`aria-label`、焦点可见
- 歌词弹层用 `role="dialog"`，Esc 关闭；曲目卡展开用 `aria-expanded`
- 密码输入框有 `aria-label`，错误提示用 `role="status"` + `aria-live="polite"`
- 装饰性画布 `aria-hidden="true"`
- 正文与背景对比度 ≥ 4.5:1（见配色一节）
- 触控目标 ≥ 44×44（移动端）
- 桌面端不要宣称 WCAG 合规——截图与 DOM 检查只能给定向风险
