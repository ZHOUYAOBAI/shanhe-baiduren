## 高影响改动清单（按优先级）

### P0 — 移动端 4 个真 bug

**M1 顶栏溢出 57px**
- 证据：390px 下 `.topbar` 高度锁死 52px，`.topnav` 实高 166px，溢出 57px；「同曲」「人物」悬在正文上且无磨砂底。
- 根因：`.topnav{flex-wrap:wrap}` + `.topbar{height:var(--topbar-h)}` 固定高。
- 修：≤720px 顶栏改 `height:auto; min-height` 并让 hero padding 用实测值；或导航改横向滚动条／底部抽屉。

**M2 整页可横滑 128px**
- 证据：`scrollWidth 518 / clientWidth 390`；`scrollTo({left:200}) → scrollX 128`。`body{overflow-x:hidden}` 挡不住（html 未设）。
- 根因：`.front-card.wide` 实宽 500px 落在 354px 栅格轨道内，grid item `min-width:auto` 不肯收缩。
- 修：`.front-grid > * { min-width:0 }`、`.front-card{width:100%; min-width:0}`、表容器 `max-width:100%`。

**M3 曲目表吸顶表头失效**
- 证据：`thead.top = -600`（滚 600px 后）—— 完全没吸住。
- 根因：`.table-scroll{overflow-x:auto}` 使计算 `overflow-y` 变 `auto`，sticky 参照系变成不纵向滚动的容器。
- 修：把 sticky 移出滚动容器，或改 `overflow: clip visible`；并补「← 左右滑动看更多列」渐隐提示（现需横滑 328px 却零提示）。

**M4 同台关系图手机不可读**
- 证据：`viewBox="0 0 1000 560"` 渲染成 308×172px（0.31×），`<text>` 13px → 实际约 4px。
- 修：≤860px 隐藏图，改为角色列表 + 「同台 N 人」；或做可拖动画布 + 点选放大。

### P1 — 导航可达性 / 触控

# 模板层加固（第三轮 · 目标：断点 / 对比度下限 / 3D 门控三条规则真正固化）

前两轮把 M1–M7 修在了**这一部戏**上。第三轮把同样的规则钉进
`script-site` 技能的**模板**，让下一部剧本自动正确 —— 并且是**代码强制**，
不是文档里写一句「记得注意」。

## 一、3D 门控：文档说有三条，代码里其实只成立了两条

SKILL.md 一直写着「三道门控，缺一不可」。逐条核对实现后发现两处漏：

### 漏洞 1 —— JS 的门控比 CSS 宽

```js
// 改之前
if (window.matchMedia('(hover: none)').matches) return;
```

CSS 用的是 `(hover: hover) and (pointer: fine)`，JS 却只判 `(hover: none)`。
触摸屏笔记本（触屏 + 触控板）**同时**满足 `hover: hover` 与 `pointer: none`，
于是手指划过卡片时 `pointermove` 照样把 `--rx/--ry` 写进去 —— 页面跟着手指转，
而不是滚动。手机上「页面自己会动」，庄重感全没。

**改法**：JS 与 CSS 逐条对齐，三条全中才挂监听：

```js
const motionOk = () =>
  window.matchMedia('(hover: hover) and (pointer: fine)').matches
  && !window.matchMedia('(prefers-reduced-motion: reduce)').matches
  && window.innerWidth > 720;
```

且**条件在运行时会变**（窗口缩小、系统切到减少动效），所以监听要能摘能挂：
`onMotionGateChange()` 监听三个 `matchMedia` 的 `change`，失效时把已经转起来的
元素立刻放平 —— 不能等下次刷新。

标题的 transform 写在**行内样式**上，权重压过任何 CSS 规则，
所以「窄屏退回平面」只能靠 JS 断开监听，CSS 拦不住。

### 漏洞 2 —— 窄屏 3D 块权重不够，被 hover 规则压过

`.tilt3d:hover`、`.front-card:hover` 的选择器权重是 **(0,2,0)**，
而窄屏块里写的是 `.tilt3d`（**0,1,0**），且窄屏块排在 hover 规则**之前**。
结果窄屏用鼠标一划，卡片照样翘起来 —— 「窄屏退回平面」是句空话。

**改法**：窄屏 3D 块移到 `main.css` **末尾**，且选择器权重与 hover 规则相同：

```css
@media (max-width: 720px) {
  .tilt3d, .tilt3d > *, .tilt3d:hover { transform: none; }
  .tilt3d::after, .tilt3d:hover::after { display: none; }
  .front-card, .front-card:hover { transform: none; }
  .hero-title-3d { transform: none; }
}
```

## 二、对比度下限：从「文档里的规矩」变成「构建时的强制」

原来 `build-site.mjs` 只验 `bg ↔ paper` 一对。审查里不合格的暗金
`#9C7A24`（3.60）根本不会被它拦下。现在改成**八项契约**逐项验算：

```
✓ paper      正文          15.30      ✓ accent-2   暗金          4.79
✓ paper-2    次级文字       8.05      ✓ accent-2   表头暗金      4.63
✓ paper-3    弱化文字       4.54      ✓ accent     总纲表头      5.66
✓ accent     强调红         5.51      ✓ on-accent  反白按钮      5.75
```

**验算时背景必须按 CSS 混色后的实际值算**。八个组合里有两组背景是
`color-mix()` 出来的（曲目表表头底、总纲表表头底），比 `bg` 更浅。
只验 `bg` 会漏检 —— 这正是上一轮漏掉的那一格：

> 暗金 `#886818` 配 bg 是 **4.65**（过），配曲目表表头底只有 **4.4996**（不过）。
> 而那个位置恰恰是 13px 的表头小字，最需要看清。

默认色板因此改为 **`#866618`**（对 bg 4.79 / 对表头底 4.63，留足余量）。

**不合格自动校正**，且是**迭代**的 —— 一条约束的修正会踩到另一条：

深色主题下 `accent` 要变亮才过得了表头底，变亮后 `on-accent`（奶油白）
就配不上了，得从奶油切成墨黑。所以校正循环几轮，每轮修一条，修完再看还剩哪条：

```js
for (let pass = 0; pass < 5; pass++) { /* 逐条修 → 再看还剩哪条不合格 */ }
```

实测：深色主题原本 `accent 总纲表头 = 4.16`（不合格），校正后 **4.51**；
浅色主题原本全过；故意做的烂色板（正文 8A7F6A / 暗金 9C7A24 / 红 E8A0A0）
八项全部自动拉回合格。

# 第四轮 · 视觉重做：「灯下九十六年」

用户看完第一版说「版面还是不喜欢，结合整体剧本内容调整颜色和 3D 效果」。
这一轮不是调色，是**把剧本自己的色彩与意象变成视觉系统**。

## 一、配色：从剧本自带的色彩词汇来

读完 `site_meta.json` 发现剧本已经把颜色写出来了 —— 六条伏笔各有一个颜色，
而且有一条注释是决定性的：

> 红心布 · 唯一高饱和的颜色。全剧只有它一直在说话。

那主色就不该是国旗红 `#BE1E2D`（亮、平、一眼是塑料），而是**朱砂**：
降了饱和又压暗，像盖在纸上的印泥。

| 角色 | 取自 | 新值 | 对 bg |
|---|---|---|---|
| 底（沉） | 旧宣纸 | `#EFE7D3` | — |
| 卡（亮） | 新纸 | `#FAF5E7` | — |
| 深块 / 表头 | 抬升一档 | `#E1D3B2` | — |
| 墨 | 主文字 | `#1D150E` | 14.62 |
| **朱砂** | 红心布 `#B5342C` 降饱和压暗 | `#A62B1E` | 5.71 |
| **灯油金** | 马灯 `#8A6413` | `#7E5A10` | 5.08 / 表头底 4.98 |
| **靛青**（新增） | 第三颗星 `#7A5C9E` + 国际歌 `#4A5A8A` 的公共暗调 | `#3B4C68` | 7.04 |

三条设计决定：

1. **底色分两级**（底比卡沉一档）—— 卡片不用靠阴影撑，自己就浮起来了。
2. **强调色只留三个，且各司其职** —— 朱砂做唯一高饱和，灯油金做暖光，靛青做冷光。
3. **冷暖成对是 3D 立体的前提** —— 受光面走金、背光面走靛青。
   只用一层灰影的卡片是「浮在纸上」，不是「被照亮」。

配套改动：语义面（卡片/表格/弹层）从纯白改成**纸色**（`bg2` 派生），
卡片不再像贴上去的塑料片；对比度契约从八项扩到**九项**（新增靛青），
构建时强制校验。

## 二、3D：把「一盏马灯」立起来

原版最大的问题不在细节，在**HERO 右半是空的**。
而且 canvas 的 `fire` 景别把火画在了 `cy = 1.02`（画面底缘外），
只剩一坨粉色光斑 —— 全剧最核心的意象，观众从头到尾没看见过。

现在它是**真的 3D**：

- 八面纸屏绕竖轴拼成柱体，`rotateY(i*45deg) translateZ(96px)`
- 每面按角度给明暗梯度（`--shade: 0% → 46%`）—— 八片一样亮就成了折屏
- 火焰用 `mix-blend-mode: screen` 放在纸屏**之前**，纸被从里面照亮
- 指针转面压在 ±13°（`initLantern3D()`），再大就转成风车
- 窄屏把灯挪到标题**上方**（文档流 `order: -1`，不用绝对定位）

另外两处 3D 改读法：

- **卡片**：从「玻璃浮起」改成「一页纸被掀起」—— 底层露一条纸边，
  投影分暖影（灯油金）+ 冷影（靛青）两半，指针高光跟着光走
- **时间轴**：五个节点点了火，火光沿连线走过去（`flame-travel`）

## 三、两个真 bug（改的过程里踩到的）

1. **标题断行把间隔号甩到行首**。中文可以在任意字间断行，
   CSS 拦不住，间隔号落到「·破晓1928」行首是排版大忌。
   改成由 JS **显式分行**（按「·」切），每行各自带 `data-text`，
   立体挤出层下沉到「行」上 —— 整块挤出跟正文的断行对不上，一眼假。
   间隔号另外用宋体做成朱砂的小点（毛笔字的间隔号落在字脚，像一粒墨点）。
2. **窄屏的灯被裁掉**。基础规则带 `margin-top: -164px`，
   窄屏只改了 `margin-left`，负的上边距留下来了 → 灯顶到画面外。
   窄屏规则必须**整条 `margin` 重写**。

## 三、改的过程里踩到的三个坑

1. **选择器权重**：基础层 `.song-table thead th`（0,1,2）会盖过增强层的

### 4. 修复的两个真 bug

**B1 · 马灯 3D 门控 `detach` 早退判断反向（initLantern3D）**
- 现象：缩窗到 ≤720px（或运行时切 `prefers-reduced-motion`）后，马灯仍跟随指针改写 `--ly/--lx` —— 监听器没被摘除。
- 根因：`detach()` 写成 `if (bound) return;`（应为 `if (!bound) return;`）。`bound=true` 时已绑定，反而直接返回，监听器永远摘不掉。`initTilt` / `initHero3D` 的 `detach` 写法是 `!bound`，三处应一致。
- 修：改 `if (!bound) return;`，并补注释。`onMotionGateChange` 在 `(hover:hover)...` / `(prefers-reduced-motion)` / `(max-width:720px)` / `resize` 任一变化即重跑 `apply()`。
- 验证：1440 移指针 `--ly=-8.19deg`；缩窗 390 后 `--ly` 被 `onLeave` 归零为 `0deg`，再移动指针仍保持 `0deg`（旧 buggy 行为会跟成 0.37deg）。

**B2 · 窄屏角色徽章 `.map-chip` 触控高度不足**
- 现象：≤720px 下 26 枚角色徽章实高 43.75px（< 44px 触控下限），且未列入「触控目标补齐」清单。
- 修：在 `@media (max-width:720px)` 补 `.map-chip { min-height: 44px; }`。
- 验证：26 枚全部 44px（`allGe44: true`）。
