## 0. 这套视觉从哪来

视觉基底取自一支抖音样片（作者 Motdes AI阿峰，2026-10-26 发布，5.8 万赞）。视频中拍的是一台笔记本屏幕，屏幕内是一个滚动的品牌站。

**本规范是逐帧复刻，不是提炼精神。** 所有色值均由视频原始像素采样得出（见下表），所有线稿画法均按视频特写逐项还原。

### 采样方法

```bash
# 逐帧抽取（4fps 高清帧）
ffmpeg -i v.mp4 -vf "fps=4" f_%03d.png

# 裁出屏幕区域（视频 576×1024，屏幕在 y=175..560）
ffmpeg -i f_030.png -vf "crop=576:390:0:172,scale=1152:-1" scr.png

# 像素采样取色
python3 probe.py   # 按色相分类统计峰值
```

### 实测色值（非目测）

| 用途 | 实测值 | 采样说明 |
|---|---|---|
| 幕布正红 | `#FF0000` | 频谱帧中饱和红峰值，n=1948 |
| 幕布暗红 | `#BF0002` | 受光衰减后的红 |
| 宣纸米白 | `#F8F2E8` / `#F2E9E3` | 地面、台面 |
| 纯白 | `#FFFFFF` | 瓶盖、按钮 |
| 墨黑 | `#0E0D12` | 近黑带蓝 |
| 瓶身蓝 | `#4FB6F9` | 三瓶同框帧 11.5s |
| 瓶身绿 | `#91EA82` | 同上 |
| 瓶身黄 | `#FDDE1F` | 同上 |

> ⚠️ **首轮用的是 `#B00000`（暗红）与 `#E0D9D6`（灰白），全部偏暗。** 采样后才发现真实主色是**纯红 `#FF0000`**——目测在手机屏上会因亮度压缩而失真，必须以像素为准。

### 视频里实际是什么（此前理解偏差）

| 我第一版的理解 | 视频真实内容 |
|---|---|
| 铜版画线稿 + 3D 罐体混排 | **主视觉是手绘插画**：人物、手臂、酒液、瓶子 |
| 金属 PBR 瓶盖 | **瓶盖是白球 + 横向螺纹排线**，无金属反射 |
| 疏朗斜向排线 | **1px 级极细密排线**，几乎不可见 |
| 抽象 3D 几何体 | **真 3D 场景**：红幕、幕布曲面、圆形画框、频谱波形 |

**核心手法**：真 3D 几何体与手绘排线线稿，**在同一透视空间里叠加**。

### 1.2 三种面（Surface Mode）


### 1.3 三色封顶原则

全站只用红／米白／墨黑。**任何区块都不允许出现第四色相。**

唯一例外是三只瓶（蓝／绿／黄）——它们是"立体实物"，需要独立色相才立得住，且面积极小。这与视频一致。

### 1.4 对比度校验

| 组合 | 对比度 | 结论 |
|---|---|---|
| `#F8F2E8` on `#FF0000` | 4.0 : 1 | ⚠️ 巨标题可用，正文需加描边或换面 |
| `#0E0D12` on `#F8F2E8` | 17.0 : 1 | ✅ 正文可用 |
| `#F8F2E8` on `#0E0D12` | 17.4 : 1 | ✅ 正文可用 |
| `#6B6B72` on `#F8F2E8` | 4.9 : 1 | ✅ 13px 以上辅助文字 |

## 4. 铜版画排线

这是复刻的核心技术。视频里的"高级感"全部来自它。

### 4.1 密度分级

**排线是 1px 级的细密刻线，不是疏朗速写。** 首版按疏朗速写做（线距 8px、线宽 1.5px），结果糊成灰面，与视频观感相差甚远。

| 级别 | 线距 | 线宽 | 透明度 | 用途 |
|---|---|---|---|---|
| 细密 | 2.0–2.4px | 0.42–0.50px | 0.20–0.34 | 瓶身、背景墙、台面 |
| 转折 | 1.7px | 0.48px | 0.46 | 瓶盖螺纹、肩部 |
| 深影 | 1.6px | 0.50px | 0.55 | 右侧暗面 |

**若隐若现是关键。** 线太密会糊成灰面，太疏会失去版画感。

### 4.2 疏密起伏必须用确定性正弦

```python
phase = i * 0.55 + seed
d += jitter * math.sin(phase)              # 位置偏移
op *= 0.80 + 0.20 * (0.5 + 0.5 * math.sin(phase * 0.9))   # 深浅
```

> ⛔ **不能用随机 jitter。** `random()` 的偏移会累积成疏密带，视觉上变成**方块状深浅不均**，整面墙像贴了瓷砖。必须用确定性正弦 —— 相位与线序号绑定，规律可控。

### 4.3 排线方向决定成败

| 元素 | 排线方向 | 原因 |
|---|---|---|
| 瓶身 | **横向** | 视频特写中瓶身排线是横的 |
| 瓶盖螺纹 | **横向** | 球面螺纹 |
| 背景墙 | **纵向** | 幕布曲面 |
| 台面 | **横向** | 水平面 |

> ⛔ **瓶身排线角度不可顺着圆柱经线**（即接近垂直），否则会变成规整条纹而非手绘网。瓶身用横向 + 弓形弧线（`curve` 参数）模拟圆柱面上的弧。

### 4.4 弓形弧线（圆柱面透视）

横向排线在圆柱上应是**两端略高、中间略低**的弧：

```python
d = (f'M{x0:.1f} {y:.1f} '
     f'Q{mid:.1f} {y + curve * (1 - ((mid-x0)/half)**2):.1f} {x1:.1f} {y:.1f}')
```

`curve` 取 0.35–1.6。取值过大（>3）会让线条交错聚簇，同样产生方块。

### 4.5 横向排线要用专用函数

通用 `hatch()` 靠角度旋转生成直线，**用在竖直瓶身上会几乎不产出内容**。横向排线必须逐根画线段：

```python
def hatch_horizontal(x0, y0, x1, y1, gap=2.1, width=0.42,
                     color=INK, opacity=0.20, seed=0, curve=0.0):
    """逐根画线段，天然限制在给定矩形内，不会溢出到相邻元素"""
```

这同时解决了"排线溢出到瓶颈/瓶盖"的问题 —— 不需要 clipPath。

### 4.6 圆面裁剪（瓶盖）

瓶盖是圆形，螺纹排线需裁剪在圆内：

```python
<defs><clipPath id="cc440"><circle cx="440" cy="180" r="30"/></clipPath></defs>
<g clip-path="url(#cc440)"> ...排线... </g>
```

圆形是凸形，clipPath 在此有效。

### 4.7 排线溢出到相邻元素

**症状**：瓶盖上方出现浅色矩形（排线溢出）。

**方案 A（优选）**：改用 `hatch_horizontal`，线段天然限制在矩形内。
**方案 B**：用 clipPath 裁剪到形体路径。但形体路径若与排线方向不匹配（如横向排线配竖直瓶身），裁剪后可能**一条都不剩** —— 这个坑踩过一次。

### 4.8 验证方法

排线是 1px 级的，**缩略图上看不见**。必须放大验证：

```bash
# 放大 2 倍并平移到瓶身位置
cat > /tmp/_zoom.html <<'HTML'
<html><body style="margin:0">
<div style="width:900px;height:600px;overflow:hidden;position:relative">
<img src="file:///.../scene-stage.svg" style="width:2000px;position:absolute;left:-760px;top:-340px">
</div></body></html>
HTML
```

用 SVG 源文件计数验证更可靠：

```python

```

## 5. 复刻场景（双轨：静态 SVG + 真 3D WebGL）

视频里的场景是**真 3D WebGL**，视觉上呈现为平面手绘插画。本项目做两条轨：

| 轨道 | 实现 | 文件 | 用途 |
|---|---|---|---|
| **静态复刻** | 程序化生成 SVG，零依赖、任意缩放不失真、能精确控制每一根刻线 | `tools/gen_svg.py` → `assets/svg/` | 首屏插画、展演屏降级兜底、规范插图 |
| **真 3D 场景** | Three.js + 自研蚀刻着色器，可交互、可动 | `assets/js/hatch.js` + `assets/js/scenes.js` | 展演屏 A/B 场景，可换视角、可随鼠标起伏 |

展演屏默认走真 3D；**模块加载失败或 WebGL 不可用时自动退回静态 SVG**，两轨观感一致，降级无感知。

### 5.2 瓶子的画法（视频特写逐项还原）

```
瓶身  纯色块 + 横向极细密排线（线距 2.1px）+ 右侧深色暗面
瓶肩  收口圆角 + 横向排线
瓶颈  白色 + 一道纵向暗线 + 一圈金属细环
瓶盖  白色球形 + 横向螺纹排线（线距 1.7px，透明度 0.46）+ 顶部高光弧 + 轮廓线
标签  黑色环带 + 米白手写体曲线
```

**没有金属 PBR** —— 视频里的瓶盖是纯白线稿球体，靠排线表现体积。

### 5.3 圆柱受光的画法

不用高光渐变，用**一块深色遮罩**表现暗面：

```python
# 右侧 40% 宽度叠一层 22% 不透明度的墨色
g.append(f'<path d="M{bx+bw2*0.30} {by} v-{bh-bw2*0.3} ... Z" fill="{INK}" opacity=".22"/>')
```

排线本身在暗面处自然更密，叠加后即得圆柱体积。

### 5.4 频谱波形

```python
env = (0.34
     + 0.40 * abs(math.sin(t * 5.3 + seed))     # 低频大波
```

白条宽 1.7px、间距 3.2px（留黑隙），高度由 `env` 决定。

### 5.5 真 3D 场景：蚀刻着色器

`assets/js/hatch.js` 的 `createEngravedMaterial()` 是 3D 轨的核心。它与首轮的排线材质有**根本区别**：

| | 首轮（光照驱动） | 本轮（恒定密度） |
|---|---|---|
| 线条密度 | 由光照暗部驱动 | **恒定**铺满表面（1px 级极细密） |
| 亮部表现 | 几乎无线 → **退化成平涂色块** | 保留刻线，是铜版画不是渲染 |
| 体积感来源 | 排线疏密 | 形体明暗（法线 vs 光向）独立承担 |
| 轮廓 | 缩放放大法 | 沿法线外扩的 BackSide 壳 |

> ⛔ **这是两轮返工里最关键的一个认知修正**：首轮以为「排线画在暗部」，实测视频后发现视频里的排线**均匀铺满整个形体**，暗部只是叠了一层更重的调子。若按首轮逻辑实现，亮部会完全无线，成品就是平涂色块而非铜版画。

着色器三步：

```glsl
// 1. 形体明暗：法线偏离光向 → 暗；分柔和段与硬边段（对应平涂插画的块面）
float ndl  = dot(N, L) * 0.5 + 0.5;
float soft = smoothstep(1.0, 0.08, ndl);
float hard = smoothstep(0.46, 0.24, ndl);
float form = clamp(soft * 0.55 + hard * 0.75, 0.0, 1.0);
vec3 col   = mix(uBase, uInk, form * uShade);

// 2. 刻线：屏幕空间平行线 + 三层正弦扰动（运笔压力）
float line = engraveLine(sp, uAngle, uLineGap, uLineW);
col = mix(col, uInk, line * uLineAlpha);

// 3. 边缘墨线：fresnel
float rim = smoothstep(0.55, 0.94, 1.0 - abs(dot(N, V))) * uRimDark;
col = mix(col, uInk, rim);
```

**屏幕空间刻线**（而非贴图）是手绘感的关键：线不随曲面拉伸变形，永远清晰等距。

```js
mat.uniforms.uLineGap.value = mat.userData.baseGap * pixelRatio;
mat.uniforms.uLineW.value   = mat.userData.baseW   * pixelRatio;
```

### 5.7 真 3D 的八个必踩坑

1. **canvas 必须有固有尺寸**：不写 `width`/`height` 时 `clientWidth=0`，`setSize()` 拿到 300×150 默认值 → 场景渲染在错误尺寸上、画面全空。必须写死尺寸 + `ResizeObserver`
2. **重建场景必须换新 canvas 元素**：`renderer.dispose()` 不释放 WebGL context 占用；复用同一 canvas → **像素全透明且无任何报错**。必须 `createElement('canvas')` 替换旧的
3. **描边套娃爆栈**：`traverse` 批量加描边时新加的也会被遍历 → 无限套娃。必须先收集再统一添加，或 `userData.noOutline` 标记
4. **shader uniform 漏声明**：`uHatchMin/Max` 写进 uniforms 但漏了 GLSL `uniform` 声明 → 编译失败 `undeclared identifier`
5. **`node --check` 检不出 ESM 语法错**：`--check foo.js` 按 CommonJS 解析，`import`/`export` 的错误会漏到运行时才炸。必须复制成 `.mjs` 再检查 —— 已固化进 `tools/sync_deploy.py` 的门禁
6. **浮点误差 → `Math.pow` 负底数 → NaN**：幕布下摆算式 `Math.pow(1 - t0, 2.4)`，当 `t0` 因误差略大于 1 时底数变极小负数，非整数次幂即 NaN，整个几何包围球失效。必须 `Math.max(0, 1 - t0)`
7. **截图验像素要用元素截图，不能用 `getImageData`**：WebGL 画布在合成后会被清空（`preserveDrawingBuffer` 默认 false），`drawImage` 取到的是全透明 → 误判成「没渲染」
8. **`networkidle0` 会超时**：3D 场景持续渲染让「网络空闲」判定永不成立。截图脚本一律用 `domcontentloaded` + 固定等待

### 5.8 交互

| 交互 | 实现 | 对应视频 |
|---|---|---|
| 鼠标视差 | 相机位置随指针缓动偏移（阻尼 0.045） | 幕布/物体随鼠标微动 |

### 5.9 路径漂移：为什么要有同步脚本

主项目与部署树目录结构不同（`tokens/` → `assets/nocturne/css/`、`assets/svg/` → `assets/nocturne/svg/`），手改两处必然漂移。**实际发生过**：A/B 场景切换写死 `assets/svg/scene-stage.svg`，部署后实际在 `assets/nocturne/svg/`，点一下就 404。

现在由 `tools/sync_deploy.py` 单向生成部署树，并内置两道门禁：

```
✓ 路径校验通过（无残留旧引用）   ← 扫部署树里是否还有 "assets/nocturne/svg/" 这类旧引用
✓ ESM 语法校验通过                ← 所有 .js 复制成 .mjs 后 node --check
```

**改动流程固定为：改主项目 → 跑同步脚本 → 再提交。**

### 5.5 幕布曲面（波浪竖线）

背景墙的竖线不是直的，是**波浪**：

```python
amp = 5.5 * math.sin(i * 0.19 + 0.7)
p.append(f'<path d="M{x:.1f} 0 Q{x+amp:.1f} {h*0.5:.1f} {x:.1f} {h}" .../>')
```

这是 3D 幕布曲面上的线在 2D 上的投影。**用 `hatch()` 的 `wave` 参数实现时须控制幅度 ≤1.6**，超过会聚簇成方块。

### 5.6 人物比例

参数化画人体极易失衡。**按真实比例算，不要凭感觉**：

```python
H = h * 0.76          # 身高
head_r = H / 15        # 头半径 → 头身比 1:7.5
sh_w = H / 2.9         # 肩宽（含长袍肩部）
hem_w = sh_w * 0.94    # 下摆 ≈ 肩宽（长袍垂坠，非斗篷）
```

> ⛔ **下摆不能比肩窄**（会成锥形斗篷），**肩宽不能按裸体算**（会显瘦高）。前两版分别踩了这两个坑，产出的是柱子与斗篷。

## 6. 动效

| Token | 值 | 用途 |
|---|---|---|
| `easeOut` | `cubic-bezier(0.16, 1, 0.3, 1)` | 强出场（滚动揭示） |

**滚动驱动**：主视觉的人物剪影随滚动微升微缩；3D 场景内相机缓慢漂移、物体轻微浮动。

**无障碍**：尊重 `prefers-reduced-motion`，关闭位移与平滑滚动。

## 8. 四套产物的关系

```
tokens/tokens.css  ←── 唯一真源（CSS 变量）
tokens/tokens.json ←── 同一套值的机读版本
tools/gen_svg.py   ←── 线稿资产生成器（排线参数在此）
        │
        ├──→ Ardot 画布设计稿（首页七屏 + 规范板）
        ├──→ index.html 原型（滚动驱动 + 复刻场景）
        ├──→ assets/svg/*.svg（程序化生成的场景与线稿）
        └──→ 本文档（规范 · 交付给协作方）
```

**改动规则**：任何色值、字号、间距的调整，先改 `tokens/tokens.css`；任何线稿画法的调整，改 `tools/gen_svg.py` 后重新生成。三者不得各自为政。

### 复刻的验证链

```
视频帧  →  像素采样（色值）  →  tokens.css
                ↓
        特写逐项拆解（画法）  →  gen_svg.py  →  assets/svg/*.svg
                ↓
        放大逐帧比对  →  原型 / 画布
```

**任何一环都不能跳。** 首版跳过了像素采样（色值全偏暗）与特写拆解（把线稿瓶当成金属瓶），两处偏差叠加，视觉上就完全不是那个东西。

## 9. 待办与已知限制

### 已知限制

0. **频谱场景为程序化律动，非音频驱动。** 视频里频谱随音频跳动，本项目是双频正弦合成（`assets/js/scenes.js` 的 `createSpectrumScene`）。若要接真实音频，接 `AnalyserNode` 替换柱高来源即可，其余不变。
1. **Ardot 画布的变量绑定在本环境不可用。** `apply_variables` 写入的 COLOR 值一律落成白色（已验证：FLOAT 正常，COLOR 的 4 种取值格式全部返回 `#FFFFFF`）。因此画布使用直接 hex 值，token 真源落在 CSS/JSON。若在正常环境下使用画布变量，可替换为 `$:Palette:red` 形式的引用。
2. **纯红与米白的对比度只有 4.0:1。** 红面上的正文不宜用米白细体，改用墨黑或加深红底。
3. **排线是 1px 级的，缩略图上不可见。** 审阅必须放大验证，不能凭整体观感判断。
4. **3D 场景的幕布下摆是几何位移，不是布料解算。** 顶点级正弦波动，视觉接近，但非物理模拟。
