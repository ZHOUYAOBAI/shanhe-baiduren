## 0. 这套视觉从哪来

视觉基底取自一支抖音样片（作者 Motdes AI阿峰，2026-10-26 发布，5.8 万赞），视频中展示了一个滚动的品牌站。我对样片做了逐帧截取与像素采样，提炼出它的三项核心特征：

| 样片实测 | 采样值 | 在本系统中的角色 |
|---|---|---|
| 正红满版 | `#B00000` | 品牌主色，幕布红 |
| 米白反白 | `#E0D9D6` | 反白文字与纸面底色 |
| 近黑 | `#08080A` | 正文与深色区块 |
| 手绘钢笔线稿 + 排线阴影 | — | **高级感的真正来源** |
| 超大高对比衬线标题 | — | 标题系统 |
| 右上角极细字体导航 | — | 导航系统 |

**关键判断：这套视觉的高级感来自铜版画线稿，不来自 3D。**

3D 几何体在样片里只承担纵深与点缀，线稿才是主角。本系统保留了这个优先级——线稿是主角，3D 罐体是配角。

而「铜版画蚀刻」本身正是 19 世纪欧洲戏单（playbill）与歌剧院海报的古典视觉语言。所以这套语言与音乐剧／歌剧剧本的内容不是硬套，是同源。

### 1.2 三种面（Surface Mode）

页面由三种「面」交替构成，这是节奏的骨架：

```
on-curtain  红面  #B00000 底 + #E0D9D6 字   →  主视觉、演出数据
on-paper    纸面  #E0D9D6 底 + #08080A 字   →  剧目陈列、创作理念
on-ink      墨面  #08080A 底 + #E0D9D6 字   →  剧本选段、联络
```

顺序遵循一条原则：**重内容用纸面，强气势用红面，沉浸阅读用墨面。**

### 1.3 三色封顶原则

全站只用红／米白／墨黑三个颜色。**任何区块都不允许出现第四种色相。**

唯一例外是主视觉里的 3D 罐体（深蓝 `#1F4E6B` / 橄榄 `#6B7A3A` / 赭石 `#C2892C`）——它们是「立体实物」，有独立色相才立得住，且面积极小。这是样片里的做法：3D 物体用彩色，线稿用单色。

## 4. 铜版画质感实现

这是本系统最难也最关键的一环。三种手法：

### 4.1 排线（Hatching）

用平行线表达明暗，线距决定灰度。

```svg
<!-- 基础排线：45°，间距 5px，透明度 0.30 -->
<path d="M0 0 L100 100" stroke="#B00000" stroke-width=".55" opacity=".30"/>
```

参数（`tokens.json` → `texture.engraving`）：

| 参数 | 值 | 作用 |
|---|---|---|
| `lineWeightPx` | 0.8 | 刻线粗细 |
| `lineGapPx` | 3.2 | 线距 |
| `angleDeg` | 45 | 主排线角度 |
| `levels` | 5 | 明暗级数 |

**交叉排线**（两组不同角度的线叠加）用于背光面，透明度减半。

### 4.2 体积排线（贴合轮廓）

体块的排线必须**沿轮廓收敛**，不能溢出剪影。

实现方式有两种，按环境选：

- **解析式**（推荐，跨渲染器一致）：把轮廓定义为贝塞尔曲线，采样出「半宽 ↔ y」对照表，每根竖线的起止 y 由该表反查得出。
- **clipPath**（SVG 原生，但部分画布解析器不支持）。

本项目的 `assets/svg/portrait.svg` 采用解析式，因此它在任何渲染器下都一致。

### 4.3 标题侵蚀

样片中的超大标题笔画有「被侵蚀」的粗糙边缘（老印刷铅字磨损感）。

| 环境 | 实现 |
|---|---|
| Web | SVG `mask` + `feTurbulence(baseFrequency 0.9)` 做字面缺口 |
| 画布 | 错版套印（offset 1.5px）+ 细划痕叠加近似 |

### 4.4 纸纹颗粒

全页叠加 5% 不透明度的 fractalNoise（`baseFrequency 0.8`），压住数字平涂的塑料感。

```css
.grain {
  position: fixed; inset: 0; z-index: 999; pointer-events: none; opacity: .05;
  background-image: url("data:image/svg+xml,...feTurbulence...");
}
```

## 5. 3D 场景（WebGL + 排线着色器）

样片里的 3D 是**真正的 WebGL 场景**，核心手法是：

> **真 3D 几何体 与 手绘排线线稿，在同一个透视空间里叠加。**

瓶身是排线线稿、瓶盖是真金属；红球是 3D 球体、轮廓是钢笔线。这不是"给 3D 加个滤镜"，而是**两种质感共存于同一空间**。

本项目用 Three.js 实现，代码在 `assets/js/`：

| 文件 | 职责 |
|---|---|
| `assets/js/hatch.js` | 排线着色器（GLSL）+ 金属材质 + 描边材质 |
| `assets/js/scenes.js` | 两个场景：瓶阵（场景 A）、圆形画框（场景 B） |
| `assets/vendor/three.module.js` | Three.js（本地化，零外链） |

### 5.1 排线着色器原理（`hatch.js`）

这是整个 3D 方案的技术核心。四步：

**① 屏幕空间刻线，不是贴在物体上的贴图**

```glsl
float d = abs(dot(sp, vec2(-s, c)));   // 到刻线族的距离
float f = fract(d / gap);
float dist = min(f, 1.0 - f) * gap;
return 1.0 - smoothstep(w * 0.5, w * 0.5 + 1.2, dist);
```

用屏幕像素坐标生成平行线，所以线条始终清晰、**不随曲面拉伸变形**。这是手绘感的关键——真实排线画在纸上，绝不会跟着物体弯曲。

**② 手绘扰动：线条不再是笔直的**

```glsl
float inkNoise(vec2 sp) {
  return sin(sp.x * 0.031 + sp.y * 0.017) * 0.5
       + sin(sp.x * 0.011 - sp.y * 0.043) * 0.3
       + sin(sp.x * 0.071 + sp.y * 0.059) * 0.2;
}
// 位置扰动
vec2 sp2 = sp + vec2(inkNoise(sp)) * gap * 0.22;
// 线宽波动（模拟运笔压力）
float w = width * uPixelRatio * (0.82 + 0.34 * (inkNoise(sp * 0.7) * 0.5 + 0.5));
```

**③ 排线强度由「曲面转折」驱动，不是由光照驱动**

这是最关键的一步，也是最容易做错的地方。

```glsl
float turn = 1.0 - abs(dot(N, V0));          // 法线偏离视线的程度
float hatchLum = clamp(lum * 0.42 + turn * 0.95, 0.0, 1.0);
```

- 圆柱**正对**处：法线≈视线方向 → `turn` 小 → 排线淡（保留底色）
- 圆柱**轮廓转折**处：`turn` 大 → 排线浓

这正是铜版画处理圆柱体的手法：**排线画在"转折"上，而不是铺满整个表面**。若改用光照驱动，正对处会因受光而完全无排线，物体就退化成平涂色块——这正是最初版本失败的原因。

**④ 交叉排线只在暗部出现**

```glsl
float shadow = smoothstep(0.45, 0.02, lum);
float b = hatchLine(sp, uAngleB, uLineGap * 1.4, uLineW * 0.85) * shadow * uCrossMix;
```

### 5.2 描边（钢笔轮廓线）

用「沿法线外扩的壳」而非 `scale` 放大，这样粗细在世界空间恒定：

```glsl
vec3 n = normalize(normalMatrix * normal);
vec4 mv = modelViewMatrix * vec4(position, 1.0);
mv.xyz += n * uThickness;      // 视图空间外扩
gl_Position = projectionMatrix * mv;
```

配合 `side: THREE.BackSide` 渲染，得到纯黑轮廓。

> ⚠️ **坑：描边套娃会爆栈。** 用 `traverse` 批量加描边时，新加的描边 mesh 也会被遍历到，于是无限套娃。**必须先收集再统一添加**，或用 `userData.noOutline` 标记排除。

### 5.3 金属（瓶盖）

`metalness = 1` 的材质若没有环境贴图会渲染成**纯黑**。解决方式是自己生成等距柱状投影的渐变环境贴图：

```js
const tex = new THREE.DataTexture(data, W, H, THREE.RGBAFormat);
tex.mapping = THREE.EquirectangularReflectionMapping;
scene.environment = tex;
```

顶部亮、中部灰、底部暗，并在正前方加一道亮带 —— 模拟影棚柔光箱，金属上会出现一条清晰高光。

### 5.4 场景构成

**场景 A · 瓶阵**（对应样片中景）

| 元素 | 做法 |
|---|---|
| 瓶身 | `CylinderGeometry` + 排线材质（斜向 25° + 交叉排线） |
| 瓶肩 | 收口圆柱，方肩香水瓶比例 |
| 瓶盖 | 圆柱 + 半球，金属 PBR |
| 黑色标签带 | `CylinderGeometry` + `MeshBasicMaterial` |
| 背景墙 / 台面 | 大平面 + 排线材质（横向 13px 线距） |

**场景 B · 圆形画框**（对应样片第一幕）

| 元素 | 做法 |
|---|---|
| 红球 | `SphereGeometry` + 排线材质（底色调成红） |
| 剪影人物 | 球 + 发型体 + 两段式手臂（肘部有转折）+ `ExtrudeGeometry` 长袍 |
| 双层画框 | 两个 `TorusGeometry`，米白 |
| 墙面 | 平面 + 排线材质 |

### 5.5 三个必踩的坑

> **坑一：canvas 必须有固有尺寸。** `<canvas>` 不写 `width`/`height` 属性时，`clientWidth` 为 0，`renderer.setSize()` 会拿到默认值 300×150，导致场景渲染在错误尺寸上、画面全空。**必须在 HTML 里写死 `width="1440" height="900"`，并配 `ResizeObserver`。**

> **坑二：重建场景必须换新 canvas 元素。** `renderer.dispose()` 不会释放 WebGL context 占用。复用同一 canvas 元素创建新 renderer 会导致**渲染完全失效（像素全透明）且无任何报错**。**解法：每次重建都 `createElement('canvas')` 替换掉旧的。**

> **坑三：canvas 绝对定位时父级要 `position: relative`，文字层要显式 z-index。** 否则 canvas 会被内容盖住，或与 flex 布局冲突。

### 5.6 参数速查

| 用途 | `lineGap` | `lineWidth` | `angleA` | `crossMix` |
|---|---|---|---|---|
| 瓶身 | 8.0 | 1.5 | π/4.6 | 0.55 |
| 背景墙 | 13.0 | 1.3 | π/2 | 0.30 |
| 台面 | 8.0 | 1.2 | 0 | 0.28 |
| 红球 | 8.5 | 1.5 | π/2.2 | 0.50 |

**排线角度不可顺着圆柱经线**，否则会变成规整条纹而非手绘网。

## 6. 动效

| Token | 值 | 用途 |
|---|---|---|
| `easeOut` | `cubic-bezier(0.16, 1, 0.3, 1)` | 强出场（滚动揭示） |
| `easeSoft` | `cubic-bezier(0.4, 0, 0.2, 1)` | 常规状态切换 |
| `d-fast` | 240ms | 悬停、下划线 |
| `d-mid` | 520ms | 常规过渡 |
| `d-slow` | 900ms | 区块入场 |

**滚动驱动**：主视觉的人物剪影随滚动微升微缩；3D 场景内相机缓慢漂移、物体轻微浮动。

**入场**：IntersectionObserver，阈值 0.12，同组元素按序延迟 90ms 阶梯进场。

**无障碍**：尊重 `prefers-reduced-motion`，关闭位移与平滑滚动。

## 8. 三套产物的关系

```
tokens/tokens.css  ←── 唯一真源（CSS 变量）
tokens/tokens.json ←── 同一套值的机读版本
        │
        ├──→ Ardot 画布设计稿（视觉稿 · 可编辑）
        ├──→ index.html 原型（可运行 · 滚动驱动 · WebGL 3D）
        ├──→ assets/js/hatch.js（排线着色器 · 可复用）
        └──→ 本文档（规范 · 交付给协作方）
```

**改动规则**：任何色值、字号、间距的调整，先改 `tokens/tokens.css`，再同步到画布与原型。三者不得各自为政。

## 9. 待办与已知限制

### 已知限制

0. **3D 展演屏需要 WebGL。** 无 WebGL 的环境（如部分老旧浏览器或禁用 GPU 的无头环境）会退化为纯色背景，页面其余部分不受影响。
1. **Ardot 画布的变量绑定在本环境不可用。** `apply_variables` 写入的 COLOR 值一律落成白色（已验证：FLOAT 正常，COLOR 的 4 种取值格式全部返回 `#FFFFFF`）。因此画布使用直接 hex 值，token 真源落在 CSS/JSON 文件。若后续在正常环境下使用画布变量，可将画布色值替换为 `$:Palette:curtain` 形式的引用。
2. **画布未做标题侵蚀效果。** 画布引擎不支持 SVG mask 近似处理，故画布稿的标题为干净字面，侵蚀质感仅在原型中实现。
